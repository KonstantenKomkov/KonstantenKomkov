# Правила сбора активности

Команда `it-activity collect` выполняет следующие действия:

1. Проверяет, что read-only токен принадлежит настроенному GitHub login.
2. Получает с пагинацией все репозитории, на которые у токена есть явное право
   чтения, включая приватные.
3. Получает с пагинацией все текущие ветки каждого репозитория и коммиты между
   началом первого из последних 365 календарных дней и текущим моментом. Пустые
   репозитории участвуют в проверке ожидаемого набора, но дают нулевой вклад и не
   запрашиваются через Git endpoints. Если GitHub дополнительно отвечает точным
   публичным сообщением `Git Repository is empty.`, репозиторий также считается
   пустым; любой другой HTTP 409 блокирует публикацию как недоступное состояние.
4. Дедуплицирует коммиты по SHA глобально, до загрузки файлового diff.
5. Оставляет только коммиты с явно настроенным авторским email и группирует их по
   календарным дням настроенного часового пояса.
6. Загружает все страницы файлов учтённого коммита, следуя документированному
   заголовку GitHub `Link` с отношением `rel="next"`. Отсутствие указанной страницы,
   повтор ответа, ссылка на другой origin или достижение лимита в 3000 файлов
   блокируют публикацию. Общая commit-статистика не используется как признак
   полноты: метрики строк считаются непосредственно по полному списку файлов.

При локальном запуске необязательные пути из `IT_ACTIVITY_LOCAL_REPOSITORIES`
добавляются к API-источникам до шага 4. Для каждого пути проверяются корень
worktree, полный non-shallow/non-partial Git history и canonical credential-free
SSH/HTTPS `origin`. GitHub origin сохраняет внутреннее полное имя для устранения
дубля с API; любой другой безопасный Git-хост преобразуется в непрозрачный
локальный идентификатор. Явно настроенная локальная история имеет приоритет над
API-историей того же GitHub-репозитория. Адаптер не выполняет сетевых операций:
lazy fetch отключён, а ошибка отсутствующего объекта блокирует результат. Коммиты
читаются только из local и remote branch refs; для строк используется полный
`numstat` относительно первого родителя с явно включённым rename detection и
отключёнными external diff/textconv.

Для строк кода используется детерминированный allowlist расширений и имён
исходных файлов. Бинарные файлы, каталоги generated/build/dist, vendored-каталоги,
lock-файлы, документация и неизвестные типы файлов исключаются. Классификация не
читает и не выводит содержимое, путь или имя приватного файла.

Публичный JSON команды содержит только дату, количество коммитов, добавленных и
удалённых строк и название настроенного часового пояса. Названия репозиториев,
веток, файлов, сообщения коммитов и авторские email в результат не попадают.

## Языки и технологии

Команда `it-activity usage` использует тот же интервал из последних 365 календарных
дней и тот же настроенный часовой пояс, что и графики активности. В годовой набор
попадают только репозитории, где за этот интервал есть хотя бы один коммит автора с
явно настроенным email. История всех веток просматривается полностью; даты вне
интервала отбрасываются, а противоречивые метаданные одинакового SHA блокируют
публикацию.

Для каждого уникального коммита настроенного автора полный файловый diff проходит
те же исключения binary/generated/vendored/lock/docs, что и метрики строк.
Расширение или специальное имя оставшегося source-файла переводится только в
закреплённое публичное имя Linguist. Язык учитывается не более одного раза за один
календарный день настроенного часового пояса, даже если в этот день было несколько
файлов, коммитов или репозиториев.

Итоговая доля языка зависит только от активных дней:

```text
share(language) = language_active_days / total_language_active_days
```

Календарный день с изменениями на нескольких языках даёт один активный день каждому
из них. Языки сортируются сначала по убыванию числа дней, затем по публичному имени;
языки без активности за период не показываются. Вычисление и округление до basis
points выполняются детерминированно целыми числами. Карточка показывает сначала
число активных дней, затем их долю.

При локальном запуске языковые дни собираются из того же объединённого набора, что
и коммиты со строками. Для явно настроенного локального клона локальная история
имеет приоритет над API-историей того же репозитория; поэтому изменения из
локальных и remote branch refs учитываются в карточке без повторного подсчёта.
Репозитории другого Git-хоста также дают вклад, но наружу по-прежнему выходят
только публичные allowlisted названия и агрегированные дни.

Allowlist содержит 825 публичных имён из
[официального реестра GitHub Linguist](https://github.com/github-linguist/linguist/blob/46e68a1dec7765b602ec9601693b10e0763436b1/lib/linguist/languages.yml)
на commit `46e68a1dec7765b602ec9601693b10e0763436b1`. Обновление списка
выполняется только явным изменением закреплённого commit и повторным запуском
тестов.

Технологии определяются для того же годового набора без чтения содержимого
manifest-файлов. GitHub-адаптер получает Git tree актуальной default branch, а
локальный адаптер — имена файлов из tree текущего `HEAD`. Оба оставляют только
разрешённые маркеры вроде
`package.json`, `pyproject.toml`, `go.mod`, Gradle-файлов и `Dockerfile`, а пути
удаляет до передачи в use case. Если recursive tree усечён GitHub, приложение
полностью обходит его поддеревья непакетным способом; ошибка любого поддерева
блокирует результат.

Публичный JSON содержит только allowlisted названия языков и технологий, итоговые
доли в basis points, число активных дней языка и агрегированное число репозиториев
для технологии.
