# Автоматическое обновление профиля

Workflow `.github/workflows/update-profile.yml` запускается ежедневно в 00:17 UTC,
вручную через `workflow_dispatch` и после изменения кода генератора в `main`.
Generated-only коммиты не запускают его повторно. Он обращается к рабочим
репозиториям только через GitHub REST API, не создаёт их клоны и не использует
cache или artifacts. Поскольку hosted runner не видит локальные клоны, workflow
только проверяет полноту доступного через API набора и не изменяет профиль.

## Настройка GitHub

В публичном профильном репозитории `<github-login>/<github-login>` задайте variables:

- `IT_ACTIVITY_GITHUB_LOGIN` — публичный login владельца профиля;
- `IT_ACTIVITY_TIMEZONE` — необязательный часовой пояс IANA; без него используется
  `Europe/Moscow`.

Задайте Actions Secrets:

- `IT_ACTIVITY_GITHUB_READ_TOKEN` — отдельный fine-grained PAT только для чтения;
- `IT_ACTIVITY_AUTHOR_EMAILS` — разделённые запятыми авторские email;
- `IT_ACTIVITY_EXPECTED_REPOSITORIES` — разделённые запятыми полные имена всех
  репозиториев, отсутствие доступа к которым должно блокировать публикацию;
- `IT_ACTIVITY_EXCLUDED_REPOSITORIES` — необязательный приватный список исключений.

Для fine-grained PAT выберите владельца ресурсов и все ожидаемые GitHub-репозитории,
которые должен собирать hosted workflow. Разрешите только чтение repository metadata
и contents; права записи токену сбора не нужны. Если организация требует одобрения
или SSO-авторизации токена, завершите их до ручной проверки workflow.

Workflow работает с разрешением `contents: read`; штатный `GITHUB_TOKEN` не может
записать или отправить изменения в профильный репозиторий. Приложению для чтения
GitHub API передаётся исключительно отдельный `IT_ACTIVITY_GITHUB_READ_TOKEN`.

## Безопасное поведение

Перед проверкой приложение требует присутствия полного ожидаемого GitHub-набора.
Ошибка доступа не раскрывает имя приватного репозитория. Hosted workflow не имеет
write-разрешения, не выполняет `git add`, `commit` или `push` и потому не может
заменить полный локальный агрегат неполным API-only результатом.

Все восемь публичных файлов — `README.md`, шесть графиков коммитов и строк и
`generated/usage.svg` — публикует только полный локальный запуск с
`IT_ACTIVITY_LOCAL_REPOSITORIES`. README получает детерминированный fingerprint
содержимого в URL каждой SVG, чтобы GitHub не показывал устаревшую закэшированную
карточку после пересчёта.

## Репозитории, доступные только с локальной машины

GitHub-hosted runner не видит клоны на пользовательском Mac. Для репозиториев,
которые нельзя выдать read-only PAT без одобрения организации, выполните тот же
`python -m it_activity generate` локально с `IT_ACTIVITY_LOCAL_REPOSITORIES`.
Формат и гарантии переменной описаны в `docs/configuration.md`.

Локальный запуск должен получать существующие GitHub-настройки и отдельный
read-only PAT через окружение, чтобы объединить локальную историю с уже
учитываемыми API-репозиториями. Приватные значения храните вне рабочего дерева,
с правами только для текущего пользователя; токен предпочтительно держать в
macOS Keychain и добавлять в окружение лишь на время процесса генератора.

Не включайте недоступные локальные репозитории в Actions Secret
`IT_ACTIVITY_EXPECTED_REPOSITORIES`: hosted workflow не сможет их прочитать и по
правилам fail-closed остановится. При локальном запуске их ожидаемые GitHub-имена
или непрозрачные идентификаторы других Git-хостов выводятся из `origin` и
добавляются к проверяемому набору автоматически.

Планировщик на Mac следует включать только после формирования полного списка
локальных клонов и контрольного запуска. До следующего полного локального запуска
все профильные карточки сохраняют последнее опубликованное полное состояние.
