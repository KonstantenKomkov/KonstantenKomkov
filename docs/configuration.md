# Конфигурация

Приложение читает конфигурацию только из переменных окружения. Файл `.env` не
используется, чтобы секретные значения не сохранялись в рабочем дереве.

Обязательные переменные:

- `IT_ACTIVITY_GITHUB_LOGIN` — публичный GitHub login владельца профиля;
- `IT_ACTIVITY_AUTHOR_EMAILS` — разделённые запятыми email, по которым определяется
  авторство коммитов;
- `IT_ACTIVITY_GITHUB_READ_TOKEN` — fine-grained PAT с доступом на чтение metadata
  и contents учитываемых GitHub-репозиториев. Переменная нужна только командам
  сбора и генерации;
- `IT_ACTIVITY_EXPECTED_REPOSITORIES` — разделённые запятыми полные имена всех
  репозиториев, доступ к которым обязателен. Значение считается приватным: если хотя
  бы один репозиторий не виден read-only токену, публикация останавливается без
  вывода имени или количества пропущенных репозиториев.

Необязательные переменные:

- `IT_ACTIVITY_TIMEZONE` — часовой пояс IANA, по умолчанию `Europe/Moscow`;
- `IT_ACTIVITY_EXCLUDED_REPOSITORIES` — разделённые запятыми полные имена
  репозиториев, которые нужно исключить из сбора;
- `IT_ACTIVITY_LOCAL_REPOSITORIES` — только для запуска на своей машине: абсолютные
  пути локальных Git-клонов, по одному пути на строку. Значение не следует сохранять
  в публичном репозитории, GitHub Actions variables или логах.

Если задан `IT_ACTIVITY_LOCAL_REPOSITORIES`, команды `collect` и `generate`
объединяют GitHub API и локальные истории до фильтрации и подсчёта. Для каждого
клона проверяется canonical credential-free SSH/HTTPS `origin`. GitHub origin
сопоставляется с API-репозиторием, а origin другого Git-хоста получает только
непрозрачный локальный идентификатор: host, namespace и имя проекта не передаются
в конфигурацию use case и не публикуются. Все локальные идентификаторы внутри
процесса автоматически добавляются к ожидаемому набору. Для явно настроенного
локального клона его история имеет приоритет над API-историей того же
GitHub-репозитория, поэтому локальные ветки попадают в графики без повторного
подсчёта. Одинаковые SHA остальных репозиториев дедуплицируются глобально как
обычно.

Локальный адаптер не выполняет `fetch`, не читает незакоммиченные файлы и не
выводит пути, URL, имена репозиториев, email или сообщения коммитов. Он читает
только метаданные достижимых коммитов и `numstat` относительно первого родителя.
Поэтому перед запуском нужные ветки и коммиты уже должны присутствовать в полном
клоне. Shallow- и partial-клоны отклоняются, а lazy fetch принудительно отключён.

Локальные клоны дополняют только графики коммитов и строк. Языки и технологии
по-прежнему берутся только из GitHub API с семантикой Linguist; недоступный API
или расположенный на другом Git-хосте репозиторий не влияет на карточку языков и
технологий.

Проверка конфигурации не выводит email и имена исключённых репозиториев:

```shell
IT_ACTIVITY_GITHUB_LOGIN=octocat \
IT_ACTIVITY_AUTHOR_EMAILS=owner@example.invalid \
IT_ACTIVITY_EXPECTED_REPOSITORIES=octocat/octocat \
.venv/bin/it-activity validate-config
```

Токен передаётся процессу через окружение. Его нельзя добавлять в URL, аргументы
команд, файлы конфигурации или вывод CI.

Пример формы локального списка без реальных значений:

```shell
export IT_ACTIVITY_LOCAL_REPOSITORIES=$'/absolute/path/to/first-clone\n/absolute/path/to/second-clone'
.venv/bin/python -m it_activity generate
```

Для локальной генерации также нужны обычные переменные GitHub API: это сохраняет
в графиках вклад репозиториев, которые уже учитывает облачный workflow. Используйте
отдельный read-only токен; не подставляйте более привилегированный токен `gh` или
SSH-ключ в `IT_ACTIVITY_GITHUB_READ_TOKEN`.

Имена ожидаемых и исключённых приватных репозиториев, а также авторские email
следует хранить в GitHub Actions Secrets, а не в repository variables.
