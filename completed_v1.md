### 2. Собрать активность из GitHub

- [x] Получать с пагинацией все публичные и приватные репозитории, доступные настроенному аккаунту.
- [x] Загружать историю всех веток не более чем за последние 365 дней.
- [x] Отбирать коммиты владельца профиля и дедуплицировать их по SHA.
- [x] Извлекать по каждому дню число коммитов, добавленных и удалённых строк.
- [x] Классифицировать файлы и исключать данные, не являющиеся исходным кодом.

Критерий готовности: на тестовом наборе публичных и приватных репозиториев агрегаты совпадают с ручным подсчётом, а повторяющиеся коммиты учитываются один раз.

Результат:

- GitHub REST adapter проверяет владельца read-only токена и получает с пагинацией все доступные репозитории, их ветки, коммиты и страницы файлов;
- use case строит 365 последовательных календарных дней в настроенном часовом поясе, фильтрует авторов и дедуплицирует SHA глобально;
- line metrics учитывают только allowlisted source-файлы и исключают binary, generated, vendored, lock, documentation и неизвестные файлы;
- CLI-команда `collect` публикует только обезличенные дневные агрегаты.

Принятые ограничения:

- используется GitHub REST API версии `2026-03-10`;
- diff из 3000 файлов отклоняется как потенциально усечённый ограничением GitHub;
- отсутствие любой страницы, противоречивые метаданные или несовпадение общей и файловой статистики блокируют результат;
- тесты не требуют реального GitHub-токена и используют только вымышленные public/private fixtures.

Артефакты: `src/it_activity/domain/activity.py`, `src/it_activity/domain/source_files.py`, `src/it_activity/application/collect_activity.py`, `src/it_activity/adapters/github.py`, `src/it_activity/adapters/http.py`, `src/it_activity/entrypoints/cli.py`, `tests/unit/`, `docs/activity-semantics.md`.
