# План разработки GitHub Activity Profile

## Цель

Создать публичный профильный README GitHub, который показывает обезличенную активность пользователя во всех доступных ему публичных и приватных репозиториях:

- количество коммитов за последние 7, 30 и 365 дней;
- количество добавленных и удалённых строк кода за те же периоды;
- используемые языки программирования и технологии;
- переключение отображаемого периода средствами, поддерживаемыми GitHub README.

В публичные файлы не должны попадать секреты или сведения, раскрывающие приватные репозитории.

## Правила расчёта

- Учитывать уникальные коммиты, автором которых является владелец профиля, во всех доступных репозиториях и ветках.
- Удалять дубли одинаковых SHA, встречающиеся в нескольких ветках или форках.
- Группировать данные по календарным дням в настраиваемом часовом поясе, по умолчанию `Europe/Moscow`.
- Под строками кода понимать добавленные и удалённые строки в учтённых коммитах.
- Не учитывать бинарные, сгенерированные, vendored-файлы, lock-файлы и документацию.
- Для приватных репозиториев публиковать только суммарные значения. Не публиковать их названия, URL, пути файлов, сообщения коммитов, email или исходный код.

## Задачи

### 4. Сгенерировать графики и профильный README

- [ ] Сгенерировать SVG-графики коммитов для периодов 7, 30 и 365 дней.
- [ ] Сгенерировать SVG-графики добавленных и удалённых строк для периодов 7, 30 и 365 дней.
- [ ] Сгенерировать отдельную SVG-карточку языков и технологий.
- [ ] Обеспечить читаемость SVG в светлой и тёмной темах GitHub и на мобильной ширине.
- [ ] Собрать `README.md` только из блоков активности, строк кода, языков и технологий.
- [ ] Реализовать выбор периода через поддерживаемые GitHub секции `<details>`; период 30 дней открыть по умолчанию.

Критерий готовности: на странице профиля можно раскрыть любой из трёх периодов и увидеть соответствующие графики без внешнего сервера и JavaScript.

### 5. Автоматизировать обновление

- [ ] Добавить GitHub Actions workflow с ежедневным расписанием и ручным запуском.
- [ ] Использовать отдельный fine-grained PAT только для чтения нужных приватных репозиториев, храня его в GitHub Actions Secrets.
- [ ] Использовать штатный `GITHUB_TOKEN` только для записи обновлённых SVG и README в профильный репозиторий.
- [ ] Не сохранять приватные клоны в публичный cache или artifacts и не выводить приватные данные в логи.
- [ ] Коммитить только фактически изменившиеся сгенерированные файлы.

Критерий готовности: запланированный и ручной запуск обновляют профиль, а отсутствие доступа хотя бы к одному ожидаемому репозиторию приводит к понятной ошибке без раскрытия его названия.

### 6. Добавить проверки качества и безопасности

- [ ] Покрыть unit-тестами границы периодов, дедупликацию, фильтрацию авторов, подсчёт строк и агрегацию языков.
- [ ] Добавить интеграционные тесты на локальных Git-репозиториях и snapshot-тесты SVG.
- [ ] Проверять, что сгенерированные публичные файлы не содержат приватных названий, URL, путей, email и сообщений коммитов.
- [ ] Запускать в CI formatter, linter, type checker, тесты, dependency audit, CodeQL и поиск секретов.
- [ ] Закрепить сторонние GitHub Actions полными commit SHA.
- [ ] Блокировать выпуск при найденных секретах или известных уязвимостях высокой и критической важности.

Критерий готовности: все проверки проходят, секреты отсутствуют в истории Git, а публичный результат содержит только разрешённые агрегаты.

## Итоговый критерий готовности версии 1

- Профильный репозиторий имеет имя `<github-login>/<github-login>` и является публичным.
- README показывает только запрошенные графики коммитов, строк кода, языков и технологий.
- Для обоих графиков доступны периоды 7, 30 и 365 дней.
- В расчётах участвуют все доступные публичные и приватные репозитории.
- Статистика автоматически обновляется ежедневно.
- В коде, Git-истории, логах и сгенерированных файлах нет секретов и сведений о приватных репозиториях.
- CI не содержит известных уязвимостей высокой или критической важности.
